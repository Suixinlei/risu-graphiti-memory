# v0.1.3 · 可靠补记与回填去重

修复 review 中两项 P1：提交失败后跳过消息，以及不同历史导出窗口复用名称而被错误跳过。同时修复真实 RisuAI 安装时发现的参数兼容问题。

- 每轮正文与游标一起写入插件本地待提交记录，约每 15 秒重试；页面重载、断网、受理后响应丢失、sidecar 重启后可恢复。只有协议 2 的 completed 回执才删除待提交正文。
- sidecar 按 group/name 核对内容，重复请求返回 pending/completed，同名不同内容返回 409。health 增加 active、pending 与 ingest_protocol。
- 回填名称采用角色、会话、原始消息绝对位置和内容摘要。旧 JSONL 核对内容后兼容续传，CLI 等待真实完成，超时/失败非零退出。
- enabled 使用宿主支持的 string 类型；整数参数初始 0 正确回退默认值。导入或更新插件后需刷新 RisuAI。

## 安装与升级

**插件与 sidecar 必须一起升级。** 先用 v0.1.3 源码及原配置重启自己的 sidecar，确认 `/health` 含 `ingest_protocol: 2`；再下载 **plugin.js**，在 RisuAI → 设置 → 插件 → ＋ 导入，允许更新和 replacer 权限，刷新页面。保留原数据库、.env 和插件存储。

- [完整安装说明](https://github.com/Suixinlei/risu-graphiti-memory/blob/v0.1.3/README.md#安装)
- **neo4j-browser.zip**：四条只读查询和 Browser 使用指南。
- **SHA256SUMS**：下载后执行 `shasum -a 256 -c SHA256SUMS`。

新安装仍从当前轮开始，不自动全量回填，也无法自动找回旧版已跳过的消息。不同 batch 边界不承诺语义去重。

## 验证

独立 RisuAI 2026.10.220 → 真实插件 → 故障代理 → 独立 sidecar → Graphiti 0.31.2 → Neo4j 5.26.32；抽取与 embedding 使用真实模型，聊天回复使用可控合成剧情。验证首次不回填、连续两轮离线、页面重载、受理后丢失响应、执行中服务崩溃、开关、会话隔离、实际提示词注入、时序失效、重叠回填和旧文件兼容。另通过类型检查、构建及发布产物核对。

完整步骤、结果和失败记录见 [E2E 报告](https://github.com/Suixinlei/risu-graphiti-memory/blob/v0.1.3/docs/verification/v0.1.3.md)。一次不同措辞的抽取仅产生归还事件，未标记旧所有权失效；该失败证据保留，采用与 UI 相同的明确当前状态表述复验。可靠保存消息不保证每次语义抽取正确。

sidecar 队列仍在内存中，恢复依赖插件本地待提交记录或 JSONL；清空存储仍可能丢失内容。固定剧情年份、全局名册、无认证和查询截断的限制保持不变。本次为非流式桌面本机链路，未验收所有宿主版本、手机、存储损坏及多 sidecar 进程。没有升级用户已有运行实例。
