# 功能 Review · 2026-10-28

范围：插件、sidecar、CLI 和安装流程。基于源码审查；离线结果见 [发布检查](verification/v0.1.2.md)。审阅阶段未读取真实聊天、访问现有服务或执行生产检查。用户随后追加的本机 Browser 配置和图谱只读检查见 [独立记录](verification/neo4j-browser-2026-10-28.md)。业务缺陷本次仅记录。

项目已有生成前检索、提示词注入、生成后异步抽取链路，支持 group 隔离、失效标记、剧情时间、文本清理及显式回填。当前适合本机早期试用，可靠入库及通用角色配置仍有缺口。

## P1：提交失败仍推进游标

- 位置：plugin/src/index.ts 的 sidecarPost、syncIngest；提交后的 storage.setItem。
- 触发：sidecar 不可达、超时或非 2xx。请求返回 null，但未检查结果就保存 msgs.length + 1。
- 影响：回复可继续，跨过的用户消息和回复可能永久漏记，服务恢复后不会自动补交。
- 复现步骤：独立测试会话记录游标 → 指向不可用测试端口 → 完成一轮 → 核对游标前进而无 episode → 恢复地址再完成一轮，核对前轮仍缺失。
- 结果：源码路径确认，未做真实 RisuAI 故障注入；修复须同时考虑确认、幂等和重试。

## P1：不同历史导出窗口复用 episode 名称

- 位置：tools/backfill.py 的相对位置 bf 名称及 name-only skip。
- 触发：同一个 group 导入不同 --last 范围或分批的 JSONL。
- 影响：正文不同但同名的 episode 会被 --skip-existing 错当作已存在。
- 复现：三条合成消息分别 --last 2 --batch 1、--last 3 --batch 1 导出；首条都叫 bf-0000-0000，正文不同。
- 结果：离线 CLI 已复现；暂时仅对同一固定文件续传。稳定标识修复需兼容原数据。

## P2：队列进度不足以证明完成，也没有持久化重试

- 位置：sidecar/main.py 的 Queue、worker、/health；tools/backfill.py 的 queue_depth 等待条件。
- worker 在抽取前 queue.get()，最后一条任务执行时 queue_depth 已可为 0，CLI 会继续或退出。
- 队列仅在内存；异常只累加 failed。config.ingest_retry 没有使用点，不能视为已有重试。
- 复现步骤：隔离环境提交抽取缓慢的 episode，比对 queue=0 和 episode 尚未出现的窗口；模拟抽取失败检查无 worker 重试。
- 结果：源码确认，未运行数据库/模型端点复验。完成判定需核对指定 episode 与事实。

## P2：全局特定故事名册影响通用性

- 位置：sidecar/main.py 的 _extra_extraction、sidecar/roster.txt。
- 所有 group 共用名册；Wells、Kagami、Villiers 等别名同时映射到多人，规范化指令存在歧义。
- 影响：无关故事的同名人物可能被改为内置角色，亲属可能误合并，频率取决于模型。
- 复现步骤：隔离环境在两个故事 group 放入共享别名、不同身份人物，检查实体名称与关系端点。
- 结果：全局加载与歧义已静态确认，未评估误合并率。

## P2：在线与离线剧情时钟不一致

- 位置：plugin/src/index.ts 的 parseStoryTime、tools/backfill.py 的 parse_story_time。
- 都固定 2026/UTC+8；在线倒序解析，离线仅首块；JS Date 可规范化越界日期，Python 会拒绝。
- 复现步骤：消息依次放入 10:00、11:00 状态块比较两条路径；再用 2 月 30 日比较日期校验。
- 结果：实现差异已确认，未做完整双路径 E2E；不宜宣称任意故事日历兼容。

## P2：查询截断也影响语义检索

- 位置：sidecar/main.py，query = req.query[:400] 后传给 graphiti.search。
- 影响：实际语义检索同样丢失第 400 字符以后的上下文，原 README 仅描述 fulltext 截断不准确。
- 结果：README 已纠正，算法保持不变。
