# v0.1.3 故障模型与 E2E 计划

编写修复及隔离验证代码前记录，2026-10-28。范围是漏记与回填名称碰撞；不改剧情日历、名册、检索算法或用户已有数据。

## 必须覆盖的失败方式

- 首次接入即离线：基线未持久化，下一轮重新初始化会跳过失败轮。
- HTTP 超时/非 2xx：不能丢弃本轮，恢复后必须重试。
- 服务已接收但响应丢失：重试必须使用同一标识，不能多次抽取/生成多个 episode。
- 202 后仍在抽取、抽取失败或 sidecar 重启：202 不是完成确认，客户端必须保留待提交正文。
- 插件刷新/重载：内存状态会丢，待提交记录必须从本地存储恢复。
- 快速连续回复/切换会话：全局 busy 不能丢弃第二轮；完成确认不能覆盖刚追加的数据；分组不能混淆。
- 开关关闭：不得继续检索/提交；重新开启后可恢复待提交记录。
- 历史截断/重新生成：不自动重放全历史，已持久化的待提交记录不随游标回退丢失。
- 空正文或本地存储失败：不提交空 episode，不虚报完成，聊天故障降级。
- 相同标识不同正文：明确拒绝，不能静默认为已存在。
- 回填不同 last/batch/重叠范围：不同 episode 不得名称碰撞；相同源位置及内容重导出应稳定。
- 相同文本在不同位置、不同会话、编辑后的文本：必须区分。
- 旧版 bf 名称兼容：不能盲信旧名称；固定旧文件可根据完整请求内容生成新标识，避免错误跳过。
- CLI 只打印 queued 或 queue_depth=0：不应报告处理成功；失败/超时必须非零退出且保留恢复信息。

## 验证层次与发布门槛

1. 合成 dump 的真实导出/回填 CLI：范围、分批、重复内容、编辑及旧文件兼容。
2. 独立 Neo4j 容器、独立 sidecar 端口、真实配置的抽取/embedding 端点：确认入库、去重、冲突、重启/响应丢失恢复、检索和失效事实。
3. 独立 RisuAI 实例和合成角色，安装最终插件，通过真实 UI 发消息；捕获聊天模型请求，核对 beforeRequest 记忆块和 afterRequest 入库，覆盖关闭、隔离、故障及插件重载。
4. 聊天回复可使用可控的 OpenAI-compatible 测试端点以复现固定事实，但 Graphiti 抽取与 embedding 使用真实模型；不得把模拟宿主或假抽取当成完整 E2E。
5. 类型检查、构建、语法与发布文件摘要。完整 E2E 不通过就不创建 Release。

使用新端口和新数据目录，不改动现有 6001/8710/7474/7687 服务。原始测试证据只含合成内容；凭据始终从本地配置读取，不写入公开文件。
