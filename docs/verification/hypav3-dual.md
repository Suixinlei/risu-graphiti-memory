# Hypa V3 双开实测 · 2026-10-28

本报告仅描述 v0.1.3 的问题。v0.2.0 已更换正式输出捕获入口；新版范围和证据见 [v0.2.0 验证](v0.2.0.md)。

**结果：v0.1.3 不应与走副模型摘要的 Hypa V3 双开。已在 6001 数据库的隔离副本中复现摘要误入库及召回反馈。** 本次只诊断，没有修改插件实现、发布新版本或操作原服务配置。

## 数据与隔离

用户明确授权复制 6001 当前数据库并测试。完整 save 目录复制到仓库外权限 0700 的私有目录；复制前、复制后和副本主库 SHA-256 相同。长会话保留 1,648 条消息及 238 条 Hypa 摘要，原 Hypa V3 配置为副模型摘要、上下文 300k。

使用 RisuAI 2026.10.220、v0.1.3 插件、独立 Neo4j 17475/17688、sidecar 18720、代理 18721。双开页面 6065；最终 Graphiti/Hypa 单开对照分别使用全新源 6066/6067。原 6001、8710、7474、7687 未被停止、重启或作为测试写入目标。

为了可重复触发摘要，测试副本窗口先设 12k，再设 80k。主模型、副模型及 Hypa embedding 全部指向本地受控端点；保留原历史与摘要，正式回复和摘要返回不同的合成标记。只将带合成标记的入库正文发送到独立 Graphiti，抽取/embedding 使用原有配置的端点。原文请求捕获和完整存档不发布。

副本仅启用 Graphiti，覆盖其 sidecar 地址，清理副本 pluginCustomStorage，禁用角色 customscript/triggerscript。模块与卡片其他设置保留；没有把该测试当作任意真实聊天模型或卡片全部脚本的质量验收。

## 结果与证据

[脱敏结果](hypav3-dual-results.json)仅包含标记判定、队列计数、episode 名称和配置核对，不含聊天原文或密钥。

| 场景 | 实测 |
| --- | --- |
| 双开且强制摘要 | Hypa 摘要结果进入 afterRequest，被当作角色回复持久化并提交 |
| 真实图谱 | 3 个不同 episode 的 content 含 HYPAV3_SUMMARY_ONLY_，均不含 CHAT_REPLY_ONLY |
| 队列 | 一次记录中有 74 条摘要、2 条正式回复待提交；正式回复排在摘要之后。此时已暂停后续提交，未等待污染全部落库 |
| 双开下一轮召回 | 实际主模型请求同时出现 1 个 Past Events Summary 和 1 个 Graphiti 时序事实块；图谱已包含误记摘要的事实 |
| 最终 Graphiti 单开，6066 | 实际主模型请求为 Hypa 块 0、Graphiti 块 1；该轮未新增 Hypa 摘要调用 |
| 最终 Hypa 单开，6067 | 实际主模型请求为 Hypa 块 1、Graphiti 块 0；停用旧页面后，该新源的公开存储 API 诊断为空，没有创建游标或 outbox |

风险不只是多花 token：旧历史的摘要会被赋予当前入库时间、进入事实抽取，后续又参与召回；大量摘要排队也会延迟真实回复入库。

## 失败及诊断过程

- 12k 窗口确实触发了 39 次摘要调用，但剩余提示词仍超限，Hypa 返回错误，未发出正式聊天请求。随后从原始快照重新准备 80k 副本。
- 本地 embedding 测试端点最初缺少 CORS 预检头，修正后才跑通。该失败属于测试设施，不归因为产品缺陷。
- 卡片在回复显示后仍停留生成阶段 4。早期单开检查读队列过早，混入了前轮回调；共享诊断端点还会被旧页面覆盖，不能作为有效对照，相关记录保留并作废。最终以全新端口载入配置，并以真实主模型请求、摘要调用计数和队列稳定值判断。
- 为读取队列计数，在私有测试插件末尾附加只读诊断：调用公开 getLocalPluginStorage API，发送 pending/摘要标记/回复标记计数到本地端点。没有修改 v0.1.3 的请求处理逻辑，也没有从浏览器内部状态伪造结果。
- 源 6001 后续主库字节哈希发生漂移，因此不宣称全程逐字节不变；只读核对确认原库没有本次测试标记，仍为原 300k、Hypa 开启、未切换测试模型。未向源库写入补丁或尝试回滚其变化。

## 复现步骤

失败方式在 [事先计划](hypav3-dual-plan.md) 中记录。完整私有证据目录的位置由本机 `/tmp/graphmem-dual-runtime-path` 保存；其中 baseline 是未经修改的快照，dual 是测试副本，neo4j 是隔离数据库，脚本及捕获也在该私有目录。它们包含真实历史和凭据，不能提交或上传。

1. 只读复制当前 save，核对主库复制前后哈希。保存原始副本，再制作工作副本；不要让浏览器连接正在修改文件的同一实例。
2. 保留长会话、Hypa 数据和副模型摘要配置，把模型与 embedding 替换为本地受控端点。摘要返回 HYPAV3_SUMMARY_ONLY_ 标记，正式聊天返回 CHAT_REPLY_ONLY。
3. 准备独立 Neo4j 和 sidecar，插件仅指向独立代理。禁用副本其他插件和角色脚本，逐项记录配置差异。
4. 在副本双开 Hypa 与 Graphiti，降低窗口到能触发摘要但仍足够完成生成的大小。本次 80k 可发送正式聊天请求，12k 不可。
5. 在 UI 发送合成测试消息，核对捕获的副模型请求和正式请求。通过正常页面操作授权 replacer；不读取浏览器隐藏状态。
6. 查询隔离 Episodic.content 的标记布尔值，核对摘要进入图谱；经公开插件 API 读取 outbox 的标记计数。暂停后续提交，保留证据。
7. 再发一轮，检查主模型提示词同时具有两套记忆块。分别用新端口载入 Hypa 单开和 Graphiti 单开配置，对照实际请求及队列变化。
8. 停止全部测试进程和隔离容器，保留快照与私有证据。不要清空或修复用户原图谱，因为本次没有向其写入。

当前建议：已有长档继续使用 Hypa V3 时先关闭此插件。修复应按请求类型排除 memory 等辅助调用，并验证流式、摘要失败和重新生成；更可靠的捕获点是宿主已提交正式聊天输出后的事件。完成联合验收前不宣称双开受支持。
