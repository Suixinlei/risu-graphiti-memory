# Hypa V3 双开隔离验证计划 · 2026-10-28

用户明确授权复制 6001 当前数据库并在隔离实例测试。原存档只读，所有副本、密钥和原文证据放在仓库外权限 0700 的私有目录，不发布。不得启动副本中的原 Graphiti 地址或其他自动联网插件。

实现验证工具前记录失败方式：

- 复制时主库或远程块变化，副本不一致；源文件与副本哈希核对。
- 副本继承原 sidecar 地址、待提交记录、自动同步或其他插件，污染原服务；启动前在副本中切断。
- Hypa 副模型摘要触发 afterRequest，被当成正式角色回复保存、提前推进游标。
- beforeRequest 向摘要请求注入 Graphiti 事实，产生摘要反馈循环。
- 双份 system 记忆内容重复、矛盾或超出模型上下文预算。
- 仅生成普通回复没有真正触发摘要，会产生假阴性；必须捕获独立摘要调用标记及正式回复标记。
- 复制真实历史后误公开原文、凭据、截图或请求捕获；公共报告仅保留计数、标记和结论。

流程：完整只读副本 → 保留当前 Hypa 数据与设置的隔离测试配置 → 启动专用 loopback RisuAI/sidecar/Neo4j → 双开并触发实际摘要 → 观察请求、待提交与图谱 → 对照 Hypa 单开与 Graphiti 单开。必要时另用受控聊天端点返回唯一合成摘要/回复标记，以区分入库来源；真实历史不发送到新增外部端点。记录配置差异、复现步骤和结果，不把模拟回执当作真实图谱结果。先诊断，不自行发布新版本。
