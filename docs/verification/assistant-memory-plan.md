# Assistant-only 异步摘要修正：失败模型与验收计划

2026-10-28，按用户明确要求：只根据 assistant 返回消息做异步摘要。已有长档隔离副本保留，原 6001 不写入。

实现前列出失败方式：

- memory/subModel 等辅助成功响应被当成聊天输出；流式没有 afterRequest 成功回调；生成失败、取消或用户消息误入摘要。
- 输出事件触发后用户切换角色，捕获错误 group；同一输出重复通知、重载后重试、重新生成/编辑复用 ID。
- UI 等待模型摘要；保存游标时丢正文；旧版本污染的 pending 自动重放。
- 摘要失败、空响应、超长文本截断、服务重启、收到 202 后丢失响应造成漏记或重复。
- 摘要已保存但图谱未提交，错误回报 completed；摘要入图失败后重复调用摘要模型。
- 摘要来源混入用户/系统提示或检索事实；跨组读取；近期摘要顺序错误；检索失败时完全丢失叙事背景。
- 历史异步摘要未完成就删除原上下文；沿用旧 Hypa 摘要重新视为 assistant 原文。
- 额外记忆没有长度限制、辅助请求被注入；正文/密钥写进公开证据。

实现范围：正式输出事件持久化 assistant 原文到新版 outbox；独立后台摘要端点与幂等回执；摘要持久化后用于近期叙事背景和 Graphiti 抽取；辅助请求不注入。老 outbox 隔离保留，历史只显式导入 assistant 原文。每轮只等待本地持久化，不等待网络或模型。

E2E：先以合成原文跑真实 sidecar/Neo4j/摘要及抽取端点的幂等、失败恢复、group 隔离；再在真实 RisuAI 的合成会话与 6001 私有副本检查 Hypa 摘要不会入库、正式非流式/流式输出都捕获、只有 assistant 原文、上下文中有近期摘要与相关事实。原始证据私有，公开报告仅标记与计数。发布与原实例升级是独立步骤，不在本轮自动执行。

## 2026-10-28 用户修正

移除额外添加的上下文压缩，保留宿主滑动窗口。验收应确认已有长 assistant 回复原样发送，没有摘要替换标记；异步摘要和独立记忆召回继续有效。此前压缩/token 缩减结果仅为已撤回功能的历史记录，不用于当前版本验收。

## 轻量收尾验证（用户要求）

摘要响应必须完整包裹在 `<assistant_summary>...</assistant_summary>` 中；缺少开头/结尾、错配、空内容、重复/嵌套标识、超长内容均失败，原文保留。只剥离外层标识后保存正文，不把标识写进图谱。验证代码先于标识实现编写。

本轮不重跑完整 E2E、不调用真实模型。用本机 OpenAI-compatible HTTP fixture 检查有效响应、截断响应、非法响应及多段原文不遗漏，再做类型检查、构建和 Python 语法检查。代码整理仅限现有改动，滑动窗口保持宿主行为，不加新功能。
